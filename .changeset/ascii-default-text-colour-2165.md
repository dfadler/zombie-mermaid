fix(ascii): default coloured output no longer paints labels near-black (#2165). `DEFAULT_ASCII_THEME.fg` was `#27272a`, which is 1.05-1.41:1 against common dark terminal backgrounds (`#1e1e1e`, `#000`, `#282a36`), so every label was close to invisible whenever colour was on. The default text colour is now `'inherit'`: in `ansi16`, `ansi256` and `truecolor` no foreground escape is emitted for text (the terminal's own foreground shows, so it is legible on dark and light), and in `html` the span is `color:inherit`. No single colour clears 4.5:1 on both dark and light backgrounds, which is why the default carries no colour instead of a mid-grey. Output change: coloured modes (`ansi16`, `ansi256`, `truecolor`, `html`) with no `theme.fg` only; the label colour code is the only difference (re-rendering with `theme: { fg: '#27272a' }` reproduces the old output byte for byte). `colorMode: 'none'`, the markdown profile, an explicit `theme`/`fg`, and all SVG output are byte-identical (checked by hashing every gallery sample and ASCII testdata input, SVG and both ASCII charsets, before and after). `AsciiTheme.fg` may now be the string `'inherit'` (the type is still `string`); `DEFAULT_ASCII_THEME.fg` changes value accordingly.

Versioning: patch per docs/decisions/versioning-and-deprecation-policy-1568.md section 1, "Output changes": it is a pure fix to an unreadable default, and the default label colour is not a documented output contract (`docs/api-reference.md` documents `theme` only as "override default colors", with no default hex values promised).
