Class boxes are now as wide as mermaid.js draws them (12.1.0 and 12.2.0 agree). Ours were 15-30% narrower on classes with members and 120 px wide at minimum, where mermaid has no minimum (an empty class `B` is 34 px). Mermaid sizes a box from the width of its text at 16px Trebuchet MS: the wider half of the centred class name or `«annotation»`, plus the widest member (members start at the centre line, so a long member leaves `name / 2 + 12` px clear on the right), plus 12 px each side. We now apply that rule with a per-glyph Trebuchet MS width table (`packages/svg-renderer/src/class/mermaid-text-width.ts`), keeping our own text-fit width as a floor so nothing overflows. Widths match mermaid on all 28 gallery samples to within 2.1 px (kerning), which brings "Class: Full Hierarchy" from 93% to 100% horizontal agreement in the layout oracle. Mermaid in a browser without Trebuchet MS (Linux) falls back to another face and draws different widths; this matches macOS and Windows, which is what mermaid.live and GitHub show there. Output change: SVG for every class diagram changes size (all 28 class gallery samples; flowchart, state, ER and every other diagram are byte-identical, checked by hashing every gallery sample before and after). ASCII output is unchanged (the exact-compare ASCII text snapshots all pass). Refs [#2128](https://github.com/dfadler/zombie-mermaid/issues/2128).

Level: patch. Per [the versioning policy](https://github.com/dfadler/zombie-mermaid/blob/main/docs/decisions/versioning-and-deprecation-policy-1568.md) section 1, layout and spacing changes are not documented output contracts, no export, option or type changes, and this closes a parity gap with mermaid.js rather than adding a feature.
