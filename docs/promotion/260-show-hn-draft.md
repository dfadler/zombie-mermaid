## Chosen hook, and the alternative considered

The issue asks for a concrete hook — "PR-rescue numbers, or a specific hard bug fixed"
— rather than a generic "we forked a thing" framing, and notes the PR-rescue campaign
(#258) hasn't produced real numbers yet (it's still a candidate list as of this draft,
see `docs/promotion/258-pr-rescue-candidates.md` — nothing has actually been merged).

So this draft leads with the **fork-fixes evidence page** instead: `demo/fork-fixes-data.ts`
already documents 27 real upstream bugs fixed, each rendered before/after by the actual
code at the actual commit (not described from memory — see that file's header comment
and `fork-fixes.ts`'s generator, which fails outright if a before/after pair renders
identically). That's a stronger, already-true hook today than PR-rescue numbers that
don't exist yet.

**Alternative considered:** lead with a single standout bug (e.g. the A* pathfinder OOM
class of issue, or the CJK/fullwidth-character rendering fixes, which show up across
several upstream PRs as a recurring pain point — see the #258 candidate list). Rejected
for the initial post because a single bug is a weaker claim than "27 fixes, each with
visual proof" — but it's a reasonable fallback angle if the repo owner wants a punchier,
narrower headline, or if HN comments push back wanting one concrete example up front
(in which case, pick the CJK-alignment cluster — it's the most-reported category across
upstream's open PRs: #99, #128, #132 in the candidate list all touch it).

**Once PR-rescue numbers exist** (real merged PRs, not just candidates), this post
should be revised to lead with those instead, per the issue's own stated dependency —
"your work, actually shipped" is a stronger hook than a bug-fix count once it's true.

## Post body

```
beautiful-mermaid (https://github.com/lukilabs/beautiful-mermaid) is a genuinely
good Mermaid diagram renderer — fast, nice-looking SVG and ASCII output, zero DOM
dependency, no headless browser required. It hit the HN front page when it launched
(https://news.ycombinator.com/item?id=47169523) and has ~11k stars and ~1.9M npm
downloads a month.

It also hasn't had a commit merged since May. 30 pull requests are sitting open,
some for over half a year — small, focused, obviously-good fixes among them.

I depend on this library, so I forked it: zombie-mermaid
(https://github.com/dfadler/zombie-mermaid). The pitch isn't "we're better," it's
"still getting fixed." Every claim on that is backed by evidence, not a changelog
you have to trust: https://dfadler.github.io/zombie-mermaid/fork-fixes.html renders
27 real bugs both before and after the fix, using the actual renderer code from the
actual commit in each case — not a description of what changed. A few examples:

- CJK/fullwidth labels (Japanese, Korean, Chinese) blew out ASCII box borders
  because width was measured in UTF-16 code units instead of terminal columns.
- `A --o B` and `A --x C` edge syntax silently dropped the target node entirely —
  no error, no edge, node just gone.
- ER diagram "zero or more" cardinality (`}o--||`) got mangled by a cardinality
  normalizer that sorted characters, which is exactly as bad an idea as it sounds.
- Arrows with no surrounding whitespace (`A-->B`) ate their own arrowhead into the
  node name, producing a node literally called `A--`.

None of these are hypothetical — click through and you'll see the actual before/after
SVG or terminal output, generated by re-running the pre-fix commit against the same
input.

It's a drop-in replacement (same API surface, MIT licensed like upstream) with active
releases, and where it makes sense I'm sending fixes back upstream too
(https://github.com/lukilabs/beautiful-mermaid/pull/142 is one example). Feedback
and bug reports welcome — that's what keeps the fork-fixes page honest.

Repo: https://github.com/dfadler/zombie-mermaid
```
